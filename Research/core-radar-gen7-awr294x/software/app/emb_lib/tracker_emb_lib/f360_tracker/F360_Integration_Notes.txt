Outstanding issues to be resolved by Simon Andersson:
1.) The RADAR code is compiled under the C89 dialect. The C89 standard API does not contain the stdint library.
    Also, including stdint.h is an Aptiv coding standard violation. An easy fix for this is to create a header file
    in the resim called reuse.h and have it include stdint.h.
2.) fminf() and fmaxf() APIs are not supported in C89.
    Affected files:
    - f360_adjust_overlapping_confirmed_tracks.cpp
    - f360_association_countermeasures.cpp
    - f360_calc_det_consistency.cpp
    - f360_get_pseudo_posn_msmt_from_associated_dets.cpp
    - f360_host_state_update.cpp
    - f360_obj_track_properties.cpp
    - my_robustFit.cpp
3.) f360_calc_mov_stat_thresh.cpp and f360_calc_obj_mov_stat_thresh.cpp are missing #include <math.h>
4.) The signbit() function used in f360_host_state_update.cpp does not exist in the C89 standard API.
5.) assert(!state_bound_fault); in sanity_check.cpp is currently commented out as it was occurring frequently.
6.) Numerous updates are required in f360_timing.cpp
7.) Add #elif defined(__DCC__) to get_wall_time.cpp
8.) All stream number and stream versions should use #defines and not static const int.
    Ex: static const int ALL_OBJECTS_LOG_STREAM_NUM = 5; should be #define  ALL_OBJECTS_LOG_STREAM_NUM (5)
9.) I recommend defining PCRESIM in the resim build and replacing all instances of #ifndef __TASKING__ with #ifdef PCRESIM
10.) Resolve differences between logging structures used by RRU and resim.
